# CaseOpenerPleerID v0.3.0 — поиск Player ID без ПК

Приложение для **поиска возможного Player ID по системным логам** оригинального Case Opener (`com.jakpok.casesimulator`).

## Основной режим: без ПК, без ADB и без других приложений

1. Открой оригинальную игру через CaseOpenerPleerID и зайди в игровой профиль.
2. В Android включи **Для разработчиков** (обычно 7 нажатий на «Номер сборки» в «О телефоне»).
3. Выбери в разделе **Для разработчиков → Создать отчёт об ошибках** (полный отчёт).
4. Когда системный ZIP будет готов, открой его через системный выбор файла в нашем приложении **или** «Поделиться» → CaseOpener ID Finder.
5. Приложение локально ищет первую строку, похожую на `Player ID: ...` либо `playerId=...`, помеченную как игровая/Unity, и выводит возможный ID с кнопкой копирования.

Отчёт никуда не загружается, системные логи не сохраняются. Это работает **только если игра действительно оставила ID в системных логах**, а устройство поддерживает создание bug report. Некоторые Android-прошивки скрывают эту функцию. Найденный ID нужно подтверждать через VaultX.

## Дополнительный режим: прямой поиск в реальном времени
На устройствах, где ранее был выдан `READ_LOGS`, доступен прежний мониторинг `logcat`. Android не выдаёт это разрешение обычному приложению самостоятельно; на Android 13+ могут действовать дополнительные ограничения/разовые запросы.

## Совместимость и безопасность
- Отдельный Android package `online.vaultx.playeridhelper`, **не заменяет оригинальную игру**.
- Не читает защищённые файлы игры и HTTPS-трафик.
- Обрабатывает выбранный пользователем ZIP/TXT локально.
- Может не обнаружить ID — наличие в журнале не подтверждено на реальном телефоне.
- APK debug-сборка. Из-за изменения отладочной подписи между GitHub Actions запусками обновление предыдущего помощника может потребовать переустановки (оригинальная игра не затрагивается).

## Сборка
JDK 17, Android SDK 35, Gradle 8.9: `gradle assembleDebug`.

Прямой APK публикуется GitHub Actions в Releases / `v0.3.0`.
